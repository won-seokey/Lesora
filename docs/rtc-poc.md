# RTC 비교 시험과 선정 규칙

현재 최종 선정: **보류**. 코드 기반 PoC만 작성했으며 실제 통화·품질·녹화 측정값은 없다. 시험 계정/사용량 승인 후 실행한다.

## 비교 가능한 최소 경로

1. 두 브라우저/PC에서 같은 provider와 room, 서로 다른 표시 이름으로 입장한다. 강사 1명은 강사 접근키, 학생은 학생 접근키를 사용한다.
2. 마이크/카메라는 입장 시 꺼져 있다. 명시적으로 켜서 상대방에게 전달되는지 확인한다. 브라우저 자동 재생 제한 시 ‘오디오 재생 허용’을 클릭한다. 현재 장치 점검은 기본 카메라/마이크 권한만 확인하며 장치 선택·스피커 테스트는 미구현이다.
3. 강사는 글자 크기가 일정한 교재/코드를 화면공유한다. 두 SDK 모두 공유 시스템 오디오는 현재 별도 검증 범위다(동일 조건에서 OFF).
4. 수동 음성 우선 모드에서 상대 음성과 공유가 남는지, 카메라 송신이 중단되는지 확인한다. 해제 후 수신이 돌아오는지 확인하고 내 카메라는 직접 켠다.
5. 중단/복구 시 이벤트, 음성 복원 시간, 중복 참가자 여부를 기록한다. SDK 자동 재연결 실패 후에는 나가기→재입장이 필요하다. 페이지 reload 후 수업 상태 복원은 미구현이다.
6. 브라우저 공유 종료 버튼, 장치 권한 거절, 입장 실패, 퇴장 후 카메라 사용 표시가 남는지 확인한다.
7. 시험마다 새 기록과 프로파일을 지정하고 JSON을 내보낸다. 앱 로그에 키/토큰을 추가하지 않는다.

최대 2개의 카메라만 표시하므로 현재는 강사/발화자 자동 고정이 없다. 표시 순서는 SDK 참가자 순서다. SDK별 자신 영상 포함 차이를 줄이기 위해 성능 측정용 관찰자는 카메라 OFF로 두고 실제 렌더된 영상 수/해상도를 측정표에 쓴다. Zoom의 송신 해상도/FPS는 아직 명시적으로 동일 값 제어하지 않았으므로 원격 attach 품질 360p를 송신 360p/15fps 보장으로 기록하지 않는다.

## 매트릭스

| 축 | 값 |
|---|---|
| 공급자 | Zoom Video SDK 2.6.0, LiveKit JS 2.23.0 (설치 후 lockfile 실제 버전 기록) |
| 브라우저 | Chrome, Edge 주요 대상 / Safari, Firefox; 정확한 버전과 OS |
| 장비 | RAM 4/8/16GB급, 실제 CPU/GPU/전원 상태; Ryzen 서버와 학생 PC 구분 |
| 규모 | 강사:학생 1:1, 1:5, 1:10 (총 2/6/11명) |
| 정상망 | 유선/안정 Wi-Fi 기준선 |
| 저속망 | 1Mbps 및 3Mbps, RTT/지연 기준 명시 |
| 지연/손실 | 150/300ms, 3/5% loss 각각 및 조합 |
| 중단 | 5/20초 완전 단절 후 복구, 3회 반복 |
| 추가 | 탭 숨김/최소화, 절전 복귀, 장치 제거/블루투스, 학교 방화벽 |

RTC 미디어는 브라우저 DevTools의 HTTP throttling만으로 제한되었다고 간주하지 않는다. 별도 시험 라우터/VM/netem 등 실제 UDP/WebRTC 경로를 제한하고 방향·인터페이스·측정 bandwidth를 기록한다. 실사용 PC 전체 네트워크를 변경하는 명령은 이 프로젝트에서 자동 실행하지 않는다. 영상 정책/공유 내용/참가자 수를 고정한 A/B 시험을 번갈아 수행한다.

## 측정

- 입장: 클릭~성공(ms), 실패 횟수/전체 시도, 정상망 p95 목표 15초. 99% 성공 목표를 작은 표본으로 입증했다고 말하지 않는다. 탐색 시험은 조건당 5회, 결정 전 표본 수·관찰 기간을 명시한다.
- 음성: 동일 낭독 표본, 수신 측 기록/관찰로 끊김 구간 수·최대/총 누락 시간. 단순 연결 상태를 음성 연속성으로 대체하지 않는다.
- CPU/RAM: OS 작업 관리자/Activity Monitor의 브라우저 프로세스 전체와 GPU 별도, 60초 기준선 후 10분 이상 관찰. 평균/peak 및 스로틀링 여부.
- 네트워크: WebRTC internals/SDK 공식 통계에서 RTT, jitter, loss, bitrate, 해상도/fps, decode 지표. SDK가 노출하지 않는 값은 N/A이며 0으로 쓰지 않는다.
- 공유 가독성: 동일 코드/교재, 수신 스크린샷/독해 과제, 공유 회복 시간. 영상만 축소하고 공유가 유지되는지 확인.
- 녹화: [recording.md](recording.md) E2E 결과, 실제 녹화 분·파일·누락 구간·복구 시간.
- 앱 JSON은 연결/품질 이벤트와 입장 경과만 포함한다. Chrome 전용 memory API나 이벤트로 CPU/음성 packet loss를 추측하지 않는다.

결과 템플릿: [results/rtc-trials.csv](results/rtc-trials.csv). 미실행은 NOT_RUN으로 기재, 누락값을 합격으로 취급하지 않는다. 내보낸 로그에 원시 음성/영상이나 실명 시험 데이터를 저장하지 말고 별도 접근 제한 증거 저장소를 쓴다.

## 필수 조건과 점수

필수 게이트: 주요 브라우저 정상망 양방향 통화/공유, 열화·단절 후 복구 경로, 자동 녹화 완전성/실패 감지, 권한/동의, 예산. 녹화 실패를 다른 점수로 상쇄하지 않는다.

통과한 후보에만 계획서 가중치 적용: 음성/저사양 35%, 녹화 20%, 총비용 15%, 개발운영 10%, 확장성 10%, 데이터/보안 10%. 각 항목 1~5점에 시험 ID·측정값·해석을 연결한다. 증거가 없으면 ‘보류’다. 현재 어떤 후보에도 점수를 부여하지 않았다.

## 비용 산정

공급자 요금 페이지를 재확인했지만 계정 견적/청구를 검증하지 않았다. 계획서의 $83.60 등 과거 예시를 확정 견적으로 재사용하지 않는다. 시나리오별 참가자 분, 녹화 출력 수, 누적 보관 GB, 재생 전송 GB, 요청 수, 기본료/포함량/초과 단가/통화/세금을 표로 계산한다.

| 시나리오 | 수업 구성 | 참가자 분 | 녹화 분(출력 1개) |
|---|---|---:|---:|
| 소규모 | 1:1, 20회 ×60분 | 2,400 | 1,200 |
| 기준 문서 | 위 +1:5, 12회 ×90분 | 8,880 | 2,280 |
| 증가 가정 | 1:10, 40회 ×90분 | 39,600 | 3,600 |

총액 = 기본료 + 각 항목 max(0,사용량-포함량)×단가 + 저장/전송/백업/서버/세금. 녹화 출력별 추가 과금이 있으면 출력 수 반영. 저장 GB≈bitrate(Mbps)×녹화초÷8÷1000, 월 신규량과 보관 개월 누적량을 구분한다. 실제 VBR 파일 크기로 보정한다. 저렴함은 음성·녹화 실패를 정당화하지 않는다.
