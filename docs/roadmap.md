## Phase 1 — 공통 실시간 강의실 MVP

의존성: Phase 0 선정/회귀 시험 자료, 수업 규모/권한 정책. 세부 작업:

1. DB migration과 auth/users: 비밀번호 해시, 세션 쿠키, CSRF, 계정 중지, 역할 테스트.
2. courses/enrollments/lessons: 소유권 검사, 일정 타임존, 예약/시작/종료 상태 전이, 중복 명령 처리.
3. 실제 사용자/참여 ID 기반 토큰, 강사/학생 레이아웃, 장치 선택 및 입장 전 점검.
4. 채팅 저장 후 전달, 메시지 UUID 중복 제거, 입퇴장 이벤트·단절/재입장 상태 복원.
5. 강사/발화자 영상 구독, 음성 우선 자동 정책·복구 지연, 오류/재시도 UI.
6. Phase 0 녹화 시작 연동을 수업 서비스에 연결하고 상태 표시(운영 완성은 Phase 2).

검증: 수업별 IDOR 음성/영상/채팅·재접속 통합 테스트, 목표 정상망 입장 p95 ≤15초·채팅 p95 ≤1초. 완료: 강사와 여러 학생이 외부 PC에서 수업·복구를 수행하고 저장된 출석/채팅을 조회한다. 녹화 없는 상태로 출시 승인하지 않는다.

## Phase 2 — 자동 녹화·다시보기·한국어 수업

의존성: Phase 1 인증/수업 상태, Phase 0 녹화 검증, 보관·동의·다운로드 정책.

1. recording_consents, 수업 시작 게이트, 동의 철회/거부 대응 UI.
2. 녹화 job/outbox 및 서명 검증 inbox, 멱등 이벤트·상태 재조회·백오프 재시도.
3. 직접 저장 또는 Zoom 다운로드→스트림 이관, 크기/재생/체크섬 검증, 분할 파일 모델.
4. 수업 참여/공개 권한 검사 후 짧은 서명 URL, 만료/삭제/공급자 원본 삭제 정책.
5. 교재 업로드/검사/PDF 열람, PPT는 변환 파이프라인 확정 전 PDF로 변환해 제공.
6. 강사 노트·숙제, 한국어 회화 실제 수업 피드백.

검증: 중복/역순/유실 웹훅, 재시도 중 종료, 권한 없는 재생, 서명 URL 만료, 동의 없는 시작 거부. 완료: 종료 후 녹화·채팅·출석을 누락 없이 권한대로 조회하고 실패를 감지·복구한다.

## Phase 3 — 코딩 공동 편집 워크스페이스

의존성: Phase 1~2 수업/권한/저장 흐름. 코벤져스 코딩 과정 출시 전 필수.

1. 과목별 workspace config 및 Monaco 지연 로드.
2. Yjs + y-monaco + Hocuspocus 수업별 문서 인증, 읽기/쓰기 권한.
3. CRDT 상태/변경 이벤트·수업 종료 스냅샷과 저장 확인.
4. 공동 커서, 언어/파일 선택, 재접속·동시 수정·권한 변경.
5. 필요할 경우 코드 기록과 녹화 타임라인 결합; 영상에 코드가 꼭 필요하면 별도 공유/녹화 템플릿.

검증: 2명 이상 동시 편집, 끊김/복구 후 상태 수렴, 권한 없는 문서 접속/쓰기 거부. 완료: 재접속·종료 후 코드 복원 및 자료와 독립된 기록 확인. 코드 실행은 제외.

## Phase 4 — 운영 안정화·보안·배포 자동화

의존성: 베타 수업 결과, 운영 규모/예산/서비스 목표.

1. 이미지/lockfile 고정, CI 배포와 롤백, secret rotation, TLS·방화벽.
2. DB/객체 외부 백업·실제 복원 시험, 보관/삭제 및 개인정보 정책 검토.
3. 녹화 실패·비용·응답시간·재접속 알림, 예산 상한과 운영 가이드.
4. VPS/관리형 DB 이관 리허설, 장애 대응·전원/회선 단절 시험.
5. OWASP 기반 인증·인가/업로드/서명 URL 점검, 브라우저 회귀/부하 시험.

완료: 복구 시간과 데이터 손실 목표를 정의하고 실제 복원·롤백을 검증, 담당자/경보/비용 한도 확보. Kubernetes는 필요성이 입증되기 전 도입하지 않는다.
